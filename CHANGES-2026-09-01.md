# Session log, 1 September 2026

What changed in the manuscript today, why, and what a reader should be suspicious of.

**Ground rules used throughout.** `main.tex` and `v1/` are frozen and were not touched — verified
with `git diff HEAD -- main.tex v1/` after every step. All work is in `v2/`. New material is green
(`\ROOF{}`), text flagged for removal is red (`\CUT{}`).

**A LaTeX trap worth knowing.** A colour set inside a group does *not* survive a column break in
this two-column layout. Bare `\ROOF{}…\OLD{}` spans silently revert to black — or to blue, if the
surrounding region is inside a `\NEW` block. Coloured passages therefore re-assert the marker at
each paragraph, and at each clause where a paragraph is long enough to split. Existing green spans
in `v1/` have this latent bug; they happen not to break today.

## New analysis

**The measured communication law.** 6.69M team-item records, 16 open-weight models, teams of 1–30
at full mesh. Round 1 precedes any exchange and its prompt equals a single agent's, giving a
no-communication baseline inside the same campaign. Per-agent prefill is then linear in peers read,
`p_in = p0 + τk`, with R² ≥ 0.998 for all 16 models and τ = 79–126 tokens (median 103, against a
120-token budget). Output length barely moves, so communication is almost purely a prefill
phenomenon. Team prefill is therefore quadratic in N: 41× more prefill at N = 30 than the same
agents run in isolation.

**Placement is bound by memory, not bandwidth.** A peer's message must stay resident in the
receiver's context for the whole forward pass, so debate inflates the KV footprint linearly in N.
Across every device/model pair, communication cuts hostable agents 5–14×. An 8 GB module cannot host
the 30-agent team it is debating with. KV width matters more than parameter count: OLMo-2-7B (MHA,
512 KB/token) holds 31 agents on an A100 where the *larger* Qwen2.5-7B (4 KV heads, 56 KB/token)
holds 347.

**A structural claim, independently confirmed.** Prefilling a token costs ~496× more than moving it
on 5G. Pricing the measured peer messages the same way gives 613× at N = 30 — reproducing §III-E's
conclusion from real multi-agent traffic rather than from one synthetic workflow.

## §VI — scaffolded, awaiting runs

The metric divides by useful output *tokens*, which is a proxy: a workflow that fails its task still
emits tokens and still scores. The infrastructure benchmark replaces that denominator with task
completion, which lets the paper answer a question the token form cannot — how many agents to use.
Success saturates in N while energy does not (Eq. 7), so joules per *solved* task has an interior
minimum.

Everything except the numbers is written. `make_figure_infra.py` reads
`results/infra_runs.csv` and regenerates the figure, table and **all nine macros**, so the prose
needs no edits when runs land. Committed placeholders render a red `??` or "pending benchmark runs".

Statistical note built into the text: at 1–2 runs over 71 tasks the binomial CI is ±6–12 pp, so the
location of the minimum is provisional; the *shape* of the trade stands regardless.
