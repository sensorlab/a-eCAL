# Code changes — 9 September 2026

Figure-generation and model code only. The manuscript is maintained outside this repository in a
`vN/` working copy and is not tracked here.

This commit also carries a small amount of uncommitted work from the 8 September session (the
`_paper_figures()` output helper and the `agentic_ecal.py` comment corrections), which had been
left in the working tree.

## New files

**`scripts/clean/roles.py`** — one functional taxonomy of agent roles, shared by every figure that
draws agents. The concrete role names differ between figures because they come from three
independent sources: the case study names its own agents, the orchestration architectures inherit
the names of the study that defined them, and the infrastructure benchmark uses its configuration
keys. Those names are left alone, for traceability to the artefacts, and the figures are unified by
functional **class** instead, carried by colour:

| class | meaning | members |
|---|---|---|
| `generate` | produces a candidate or a plan | planner, proposal, proposer |
| `transform` | refines ONE line of work | analyst, writer, critic, refiner, verifier |
| `ground` | acquires state external to the workflow | retriever, inspector |
| `aggregate` | reduces COMPETING candidates | manager, synthesiser, duelist |

The transform/aggregate line is drawn at *competing candidates*, not at fan-in: a cascading refiner
reads its own history and still refines one draft, whereas a duelist picking one of two rival
answers, and a synthesiser merging three, both reduce a candidate set. `role_class()` raises
`KeyError` on an unknown name deliberately, so a new role must be classified rather than silently
defaulted.

`ground` has no counterpart in the orchestration taxonomy, which admits neither retrieval nor
tools. That absence is a result rather than an oversight.

**`scripts/clean/fig_topologies.py`** — generator for `topologies_v1.pdf` (the eight orchestration
architectures), previously untracked. Now sources its palette from `roles.py`.

**`scripts/clean/make_figure_overview.py`** — generator for `fig_overview.pdf`, the framing figure.
Rewritten from a two-layer form (workflow graph above a substrate, joined by projection lines) to a
single diagram with tier on the vertical axis and workflow order on the horizontal, so that
placement is position. The previous version was authored 7.1 in wide but included at
`\columnwidth`, which put its labels on the page below 3 pt; everything is now sized for the column
it is placed in. It computes and prints the prefill-to-transport ratio it annotates
(`crossing_ratio()`: 496x for a 2 700-token hand-off on a 5G bearer) rather than hard-coding it.

## Modified

**`agentic_ecal.py`**
- Removed equation numbers from comments and docstrings. They referred to the numbering of an
  earlier manuscript revision and had drifted; the comments now name the quantity ("the two-rate
  model", "the prefill rate") instead of a number that goes stale on every reorder.
- `four_agent_rag_workflow()` docstring no longer claims to settle audit finding C5, which
  `docs/o2-audit-report.md` records as still open for the co-authors, and no longer quotes energies
  that had gone stale twice. It points at `make_figure_workflow.py` for current values.
- `llm_call_energy()` docstring now states explicitly that it derives its rates from datasheet
  quantities rather than from the measured `TWO_RATE` coefficients, since the two paths had become
  easy to confuse once both were plotted.

**`make_figures.py`** (Figs. 2, 3 and the communication figure)
- Added `datasheet_energy_per_query()` / `datasheet_curve()`: the same two-rate form with rates
  **derived** from `N`, `beta`, `P`, `B_HBM`, `eta_pre` rather than fitted, so the figure can show
  the gap between prediction and calibration. It splits by `n_calls` where the calibrated path does
  not, because the derived decode rate carries a cache term evaluated at the call's mean context
  and is therefore quadratic in it — applying it to per-query totals would price one enormous call
  and inflate that term.
- Fig. 3 restyled: measurements as markers only so the overlays stay legible; panel (b) batches on
  a blue ramp (orange withdrawn, since it denotes Llama elsewhere); solid = calibrated,
  dashed = datasheet in both (a) and (b); composite `HandlerTuple` legend keys so a coloured
  overlay is not represented by a single grey sample.
- Panel (c) reverted to measured-only. The overlay overshot badly at large batch (1.58 against a
  measured 1.42 on Qwen, 1.45 against 1.17 on Llama); the overshoot is anchored at `N=2`, where the
  model under-predicts by 46–63% at `b=256`, so plotting it displayed a localised residual as a
  systematic slope error. The reason is recorded in the code.

**`make_figure_workflow.py`** (Fig. 4)
- Agent boxes tinted by functional class via `roles.py`, with a class key between title and
  schematic.
- Panel (d) now covers all three serving batches. `E_W` is 281.5 J at `b=64` and 238.1 J at
  `b=256` — 18% apart, thinner than the line width on a seven-decade log axis — so the batched
  regime is drawn as a band bounded by the two rather than as two overprinting lines.
- Schematic spacing: boxes 0.72 -> 0.84 tall with the two text lines at 0.68h/0.25h, and the axes
  y-range trimmed to the drawn content. The axes previously ran `ylim(0, 4.05)` over content
  spanning ~0.4–3.6, and that dead space read as a gap between the panel and the row beneath it.

**`make_figure_infra.py`** (Fig. 9)
- Added `COMPOSITION` and `class_grid()`: each topology carries a fixed four-slot grid recording
  which functional classes it instantiates, filled where present and outlined where absent. The
  marks in this figure are per-topology rather than per-node, so composition is how the shared
  class colours apply here.
- Bars and markers made neutral so the grid carries the colour signal, and panel (c)'s two series
  recoloured off the class palette to avoid collision.

**`make_figure_capacity.py`, `make_figure_topology.py`, `make_figures_placement.py`,
`make_figures.py`, `make_figure_infra.py`** — all now resolve their output directory through
`_paper_figures()`, which picks the highest-numbered `vN/` working copy that exists, instead of
hard-coding `v2/figures` or the repo-root `figures/`. The hard-coded defaults went stale on every
revision and silently wrote into a superseded copy.
