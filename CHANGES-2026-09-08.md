## Fig. 6(a) — the denominator was invisible

The four weight classes hold **3, 7, 3 and 3** of the 16 models. Every cell is either the whole
class or Orin's 2 of 3:

```
                <8 GB    8-16     16-32    32-64
  orin           2/3      0/7      0/3      0/3
  l4             3/3      7/7      0/3      0/3
  rtx4090        3/3      7/7      0/3      0/3
  agx_orin       3/3      7/7      3/3      3/3
  a100           3/3      7/7      3/3      3/3
```

The panel printed the numerator alone. Three problems compounded:

1. the denominator changes per column and was stated nowhere, so "3" read as worse than "7";
2. the colour scale was shared across columns with different maxima, so the `<8 GB` column rendered
   permanently fainter than `8–16` even where both were fully satisfied;
3. the colorbar was labelled **"models (of 16)"** while running 0–7.

Together these invited exactly the wrong reading — that fewer light models fit than medium ones.

**In `make_figure_capacity.py`:** `grids()` now also returns the per-class population; `heat()`
takes a `denoms` argument and, when given, colours by the fraction `n/N` and labels each cell
`n/N`; the colorbar reads *"fraction of weight class"* over 0–1; and a `0` cell shows `0/7` rather
than `--`, since with a denominator present the zero is informative. Panel (b) passes no `denoms`
and is untouched.

Every fully-satisfied class now renders the same colour whatever its size. The console table the
script prints carries the denominator too, so the figure and the log agree.

## Fig. 6(b) — colorbar, not data

The session-log entry worth keeping: **this was already in the version we pulled**, not introduced
by the panel-(a) work. Verified by rendering `git show HEAD:` of the file side by side.

Guarded on `log`, so panel (a)'s linear 0–1 colorbar is unaffected. Only `10¹` remains. Cells,

## The protocol span — `5.7\times10^{5}` is wrong twice

The number appears in §V-B and again in the Fig. 7 caption. At K=3 the three candidate ratios are

| ratio | value | orders |
|---|---|---|
| KV / full context | 56,936 = **5.69×10⁴** | 4.76 |
| KV / incremental | 370,086 = **3.70×10⁵** | 5.57 |
| KV / summary | 238,765 = 2.39×10⁵ | 5.38 |

and none of them is 5.7×10⁵. Nor is it a depth artifact: swept over K=1…8, KV/incremental runs
123k, 247k, 370k, 493k, 617k — stepping *over* 5.7×10⁵ between K=4 and K=5 without landing on it —
while KV/full-context asymptotes to ≈60k.

**Where 3.7×10⁵ comes from.** It is not read from anywhere; it is the ratio of the two extreme
protocols, at the figure's own parameters (N=4 agents, K=3 rounds → 12 hand-offs, 250 tokens per
turn, f = 17 bit/token):

```
incremental (cheapest): 12 msgs x 250 tok x 17 bit          =         51,000 bits
KV migration (dearest): 12 msgs x 131,072 B/tok x 1500 tok x 8
                                                            = 18,874,368,000 bits

span = 18,874,368,000 / 51,000 = 370,086 = 3.70 x 10^5
```

The KV context is `N*K*p_out/2 = 1500` tokens, and 131,072 B/token is Llama-3.1-8B's cache entry.
Ordered cheapest first the four protocols are incremental 0.051, summary 0.079, full context
0.3315, KV migration 18,874 Mbit — so the span is KV over incremental, and full context is not an
extreme at all.

**How it arose.** The mantissa 5.7 matches KV/full-context (5.69×10⁴) to three significant figures.
The exponent matches the *words* of the preceding sentence, "five orders of magnitude above the
transcript", which is 4.76 rounded up. The number is a splice of the correct mantissa with an
exponent imported from the rounded prose describing that same ratio; the "therefore" joining the
two sentences is the seam.

**Why the fix is 3.7×10⁵ and not 5.7×10⁴.** Tempting as the mantissa evidence is, the smaller
value inverts the paragraph's own conclusion. The sentence ranks three spans and concludes that
"what a hand-off contains dominates both where it is sent and how it is carried", and the bearer
span is $10^{-3}/10^{-8} = 10^{5}$:

- at **3.7×10⁵** → protocol > bearer (10⁵) > architecture (4.8×). The claim holds.
- at **5.7×10⁴** → protocol < bearer. The bearer would dominate the protocol by 1.8× and the
  sentence would assert the opposite of its own numbers.

Two further reasons agree: "spans" ordinarily means the range between extremes, which is KV over
incremental; and the caption's parallel construction — "costs $6.5\times$ an incremental hand-off,
and … times as much" — makes the incremental hand-off the comparator in both places. Same
substitution, both occurrences.

**This is an inference about intent, not a derivation.** The published number matches neither
candidate, so somebody has to decide which comparison the sentence was making. Both readings are
internally coherent:

| if the sentence meant | correct value | what else must change |
|---|---|---|
| the span of the protocol family (dearest / cheapest) | **3.70×10⁵** | nothing; the ranking and conclusion stand |
| the KV-vs-transcript gap the previous sentence describes | **5.69×10⁴** | the closing clause — the protocol would no longer beat the bearer |

We took the first. An author who knows the sentence was always about the transcript comparison
should take the second and rewrite the conclusion, because at 5.69×10⁴ the bearer wins.

**Optional, and recommended.** With the corrected value the closing clause rests on two very
different margins: the protocol beats the *architecture* by five orders (3.7×10⁵ / 4.8 ≈ 7.7×10⁴)
but the *bearer* by only 3.7×. "Dominates both" flattens them, and a referee who divides will
notice. Suggested replacement for the final clause:

```latex
what a hand-off contains dominates the choice of graph by five orders of magnitude and outweighs
even the choice of bearer.
```

**Leave #35 alone.** "Five orders of magnitude above the transcript" is a *different* comparison —
KV against full context, 4.76 orders — and is correctly rounded. It verified clean.
